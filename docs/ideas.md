## 小さいが毎日効きそうなもの
- 打ち間違いの直し：直前に打った単語を、IME のオン・オフを逆にして打ち直す。CapsLock の誤爆（`hELLO`）も直す。
- マイクの全体ミュート：アプリに関係なく 1 打鍵でミュートし、状態を常に見えるようにする。
- アプリごとの IME 状態の記憶：アプリごとに前回の IME の状態を覚えておき、切り替えたときに自動で戻す。
- すぐメモ：小さな入力欄を出して 1 行書き、Enter でファイルの末尾に追記して閉じる。

## 変わり種
- 画面の変化待ち：画面の範囲を指定し、そこが変わったら通知する（ビルド、ダウンロード、レンダリングの完了待ち）。
- 窓のライブ縮小表示：別の窓の一部分を、小さな常時表示のウィンドウとして画面の隅に出す（DWM の仕組みを使う）。
- キー使用統計：どのキーをどれだけ使ったかを記録し、使われていない割り当てや、よく使うのに遠い割り当てを見つける。
- 作業ログ：アクティブなウィンドウのタイトルを時間とともに自動で記録し、後から検索できるようにする。
- 集中モード：アクティブなウィンドウ以外を暗く覆う。

## 割り当ての空き（親指キーまわり）
- 変換 → 無変換 / 無変換 → 変換 の 3 キー（`keymap/chord_keys.ahk`、`chord_ordered_keys.ahk`）：空いているキーがまだ多い。Enter 系は Shift / Ctrl / Alt / Ctrl+Shift が済み。未割り当ての組み合わせの候補：Ctrl+Alt+Enter、行末へ移動してから Enter。
- 2 キー自体（無変換 → 変換、変換 → 無変換）に処理を割り当てるときは `Chord_Begin(順, 関数)`（`Lib/chord.ahk`）。ただし 3 つ目のキーを押す前に働く。

## キーの同時押し（親指キーを使わない 2 キー）
2 つのキーを同時に押して処理を呼ぶ（例：`f` + `j`）。親指キーを使う割り当て（`keymap/hold_keys.ahk`）とは別に、親指を使わない「押す回数 1 回」の入口が増える。ただし**何もしないと通常のタイピングが遅くなる**ので、下の懸念を先に潰す。

### 懸念点
- **遅延**：文字キーが同時押しの片方になると、AutoHotkey は先に押したキーをすぐには入力できない。`A & B::` の形だと、A は離したときにやっと入力され（長押しのリピートも止まる）、`~A & B::` の形だと、A がそのまま入力されてから処理が働く。自前で待つ形（判定の時間だけ保留）なら、保留した分（20〜40 ms）だけ、そのキーの入力が遅れる。
- **順番の入れ替わり**：保留している間に、組み合わせに関係ないキーを押すと、そちらが先に入力される（`f` を保留 → `x` を押す → `xf`）。`A & B::` の形でも、速く打つと `da`（`d` を押したまま `a` を押す）が `ad` になる。保留中は全キーを受け止めて順番を保つ必要があるが、これは重い。Space の割り当てが破綻しないのは、Space が全文字キーと組み合わさっていて、どれも順に受けるため。
- **誤爆**：ローマ字入力・英語で、続けて打つ 2 キー（`kl`、`gh` など）が、同時押しと判定される。ローマ字にも英語にも出てこない組み合わせなら起きにくい。
- **既存の仕組みとの重なり**：親指キーを押している間（`Space + j` のあとに `f` など）、入力待ち・モード中（`IH_waiting`、Vimium C 風ヒント、カーソル移動）、Shift 長押しモード、Ctrl / Alt / Win を押している間は、同時押しを止める。IME の変換中も止めたいが、判定できない。
- **試験**：本物の同時押しは作れない。`SendInput("{f down}{j down}")` のように続けて送り、別プロセスから `SendLevel` 0 で送る必要がある（自分の送ったキーには自分のホットキーが働かない）。判定の時間まわりは手で確かめるしかない。

### 影響を小さくする方向
1. **第 1 キーの働きが無害なキーを起点にする**（遅延ゼロ）：`~LShift & RShift::` のように `~` を付けると、押した瞬間はそのまま通るので遅れない。第 1 キーを押しただけで何も起きないキー（修飾キー、マウスボタン、Esc 以外の非文字キー）なら、副作用がない。
2. **文字キーなら、続けて打つことがない組み合わせだけにする**：両手に分かれ、ローマ字にも英語にもほぼ出てこない 2 キーだけ。誤爆が出にくく、判定の時間を短く（25〜40 ms）できる。
3. **保留するのは、組み合わせに入っているキーだけ**。ほかのキーは素通し（遅れない）。
4. **直前に別のキーを打っていたら（約 80 ms 以内）、同時押しとは見なさず通常入力にする**。連続で打っている最中の誤爆を防ぐ。
5. 使わない人のために設定でオン・オフできるようにする（`config.ahk`）。

### 割り当ての候補（現在の割り当てを見て）
親指キーを使う割り当て（`hold_keys.ahk`）は、親指を押している間だけ働くので、親指を押していなければ重ならない。入力待ちの起点（Caps、かな）、`^+!F11` / `^+!F12` とも重ならない。使われていないのは次の組み合わせ（割り当てる前に keymap を検索して確かめる）。
- **遅延なし（方向 1）**
  - 左 Shift + 右 Shift：両手で押す。修飾キー同士で副作用がない。ただし左 Shift は Shift 長押しモード（`Lib/shift_hold.ahk`）が送るので、モード中は止める。
  - マウスの左ボタン + 右ボタン：`~LButton & RButton::`。マウスを持ったままの操作になるので、キーボードのみの方針とは別枠。
- **遅延あり・誤爆が少ない（方向 2）**：ホーム段で両手に分かれる組み合わせ。
  - `f` + `j`（人差し指同士）：最も押しやすい。英語の `fjord` 以外は出てこない。
  - `d` + `k`（中指同士）、`s` + `l`（薬指同士）、`a` + `;`（小指同士）。`sl` は英語の `slow` などに出る。
  - 同じ手の隣り合うキー（`d` + `f`、`s` + `d`）：ローマ字にも英語にも出てこないので使える。人差し指 + 中指で押せる（下の「分割キーボード」）。`j` + `k` のように、続けて打つことがある組み合わせは避ける。
  - 避ける：`g` + `h`（`night`、`high`）。
- **親指キー系の空き（新しい仕組みが要らない）**：`hold_keys.ahk` の「未割り当て」のうち、`変換 / 無変換 + LAlt / RAlt / LShift / RShift`、`Space + LShift / RShift / RControl`。いまの仕組みのまま使える。

### 見立て
- 効果が見込めるのは `f` + `j` のような、押しやすく、タイピングで出てこない 1〜2 組だけ。たくさん割り当てる用途には向かない（割り当て数に比例して、保留するキーが増えて遅くなる）。
- まず親指キー系の空きを使い切り、足りなければ `~` 方式（遅延ゼロ）、それでも足りなければ `f` + `j` を試す順がよい。実装するなら、まず自前の保留なしで、`A & B::` と `~A & B::` の遅れを実機で測る。

### 分割キーボード＋トラックボールへの移行（Keychron Orca Echo。仕様は未確認）
右手がトラックボールで、クリックのボタンがない（または足りない）場合の検討。モード切替はせず、文字入力とマウス操作を行き来したい。
- いまの Space + `n` / `b`（クリック）、`,`（ダブルクリック）、`.`（右クリック）は、押して離すだけで、ボタンを押し続けられない。ドラッグは `Mouse_ToggleDrag()`（`Lib/mouse_cursor.ahk`）。「左手でボタンを押したまま、右手でトラックボール」には、押している間だけ押した状態になる入口が要る。
- 案：左手の人差し指 + 中指（`d` + `f`）を左ボタン、薬指 + 中指（`s` + `d`）を右ボタンにする。親指を使わず、モードもない。
- **AutoHotkey だけで作るのは避ける**：文字キーを保留する形になり、順番の入れ替わりと遅延が出る（上の懸念）。
- **ファームウェアの同時押し（QMK の Combo）でマウスボタンを出す**のが本命。キーボードが全キーを順番どおりに出すので順番が入れ替わらず、押している間だけボタンが押された状態になる。OS からは本物のマウスボタンに見えるので、`LButton` を使うホットキー（`screen_capture.ahk` など）もそのまま働く。
  - 要確認：Combo とマウスキーに対応しているか、設定画面（Keychron Launcher）だけで足りるか、QMK 本体を書き換えるか。
- 代替：左手側の使わないキー 2 つを、マウスボタンのキーとして直接割り当てる（同時押しなし）。
- 親指キー（変換・無変換・Space）に当たるキーが出るかも確認する。US 配列系だと標準では出ないので、キーコードの `INT4`（変換）、`INT5`（無変換）、`INT2`（かな）で割り当てる。親指キーが足りなければ、Caps / かなの入力待ちの起点を含めて割り当てを見直す。

## 優先度の見立て
- 実装が軽く、効果がすぐ出るのは 2（OCR）・3（計算）・4（窓ハープーン）。最初に手を付けるならこの 3 つ。
- 5・6 は使う場面が決まっているが、効く場面では非常に効く。
