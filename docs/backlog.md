## 検討メモ

### 1. フォーカス中の部品のキャプチャ（実装済み。あまり使わないので割り付けを外し、`Lib/archive/capture_extras.ahk` に移した：`Cap_Focus`）
- 試したこと：エクスプローラーで F6 を繰り返すと、UI Automation の `GetFocusedElement` が次のような「部品（葉）」を返す。
  - ファイル一覧：項目 → 一覧　　列見出し：見出し項目 → Header → 一覧　　下部：ボタン → ツールバー → ステータスバー
  - フォーカスは「ペイン全体」ではなく中の 1 つの部品を指す。見た目のペインを撮るには、親をたどる操作が要る。
- 決めたこと
  - 親・子の切り替えはホイールとキーボード（K：外側、L：内側）の両方。`cap-area` と共通。
  - 「ペインらしい親」への自動ジャンプはしない。アプリごとの個別対応は作り込まない（`principles.md`）。部品の種類での判定もしない。
  - 呼び出しは「画面キャプチャ」カテゴリの一項目として置く。
- 動作：枠がフォーカス中の部品に付き、フォーカスを動かすと追従する。Tab / F6 はホームポジションから遠いので、選択中だけ F → Tab、A → Shift+Tab、D / E → F6、S / W → Shift+F6 を割り当てる（矢印キーはそのまま）。決定は左クリック・Enter・G・H。マウスの位置は無視。選んでいる間に画面が変わるため、決定後に撮り直す。
- 注意：Electron 系・ブラウザのページ内は UI Automation で取れる部品が少ない。

### 2. Vimium C 風ヒントの暗転（済：実機で問題なしを確認。当時の名前は「ヒントモード」）
- 原因の見立て：ラベルの窓が「全画面の窓を色抜き（`WinSetTransColor`）で透かす」方式だった。`Show` で窓を出したあとに色抜きを付けていたため、その間は全画面が暗い色で塗りつぶされて見える。手元の環境では再現できなかったが、実機での確認で解消した。
- 直し方：全画面の色抜きをやめ、ラベルの矩形だけに窓を切り抜く（`SetWindowRgn`）。半透明の指定は `Show` の前に付ける。文字を打ってラベルが絞られたときも、切り抜きを作り直す。

### 3. キー割り当ての見える化（実装済み：クイックメニュー S → K、`keymap`）
- 形：JIS 配列のキーボード図の上に、レイヤーごとの割り当てを表示する HTML を作り、ブラウザで開く。レイヤーはタブで切り替える（変換 + / 無変換 + / Space + / Caps → / Space+F → / Space+A → / かな →）。数字キー 1〜7 でも切り替えられる。
- 作り方：`keymap/hold_keys.ahk` と `keymap/leader_keys.ahk` を開くたびに読み込んで作る。割り当てを変えても、手で直さずに最新になる。表示する文字は、行末のコメントがあればコメント、なければ処理から作る（`SendInput` の中身はキー名に直す。関数名は `Lib/keymap_view.ahk` の `KM_FUNC_NAMES` で日本語にする）。
- 表示：起点のキーは黄色、割り当てのあるキーは青。長い説明は、キーに載せると途中で切れるので、「（」の手前までを表示し、全文はマウスを載せると出る。レイヤーの全件は図の下の「全割り当て」で開く。
- 制限：マウスのボタン・ホイール、PgUp / PgDn のようにキーボード図にないものは、図の下の表に出す。`Lib\` の中のホットキー（Insert での再読み込みなど）や、入力待ちの中のキー（Fn キー入力モードなど）は対象外。

### 4. 日付入力（実装済み：クイックメニュー N → N、`Lib/date_input.ahk`）
- 流れ：呼び出す → 日付を調整 → 確定 → フォーマットを選ぶ → 確定 → 入力。確定前の日付・フォーマットはツールチップで表示する。
- 日付の調整（呼び出した直後は現在の日付。初期フォーマットは `yyyy/mm/dd`）
  - K：1 日戻る　　L：1 日進む　　J：10 日戻る　　;：10 日進む
  - H または N で日付を確定し、フォーマットの選択へ進む。
- フォーマットの選択
  - L：次　　K：前　　J：先頭　　;：最後
  - H または N で確定する（確定したフォーマットで日付を入力する）。
- 決めたこと
  - 呼び出しはクイックメニューの「日付・時刻」（N）の N と、Space + F → i。別のキーへ移すときは `quick_menu.ahk` の `this.Add("N", "N", "date-pick", ...)` と `keymap/leader_keys.ahk` を直す。
  - フォーマットの候補は `Lib/date_input.ahk` の `DATEINPUT_FORMATS`（12 種。先頭が初期値）。
  - Esc / Caps でキャンセル。60 秒操作がなければ自動でキャンセル。確定後は、元のウィンドウへ IME を半角にして入力する。
- 未定
  - 呼び出しのキー割り当て（`ideas.md` と同様、実装するときに決める）。
  - フォーマットの候補の見直し。

### 5. PowerPoint の詰め合わせ（土台ができた：クイックメニュー P、`Lib/powerpoint_pack.ahk`）
- 方針：`principles.md` の「アプリ専用の機能を入れる条件」のとおり、標準の操作では手数がかかるものだけ、PowerPoint の COM で作る。PowerPoint が前面にあるときだけ動く（ほかのアプリでは「PowerPoint が前面にありません」と出る）。
- 土台の内容（P → キー）
  - 整列：L 左、R 右、T 上、B 下、C 左右中央、M 上下中央（図形が 1 つならスライドに対して、2 つ以上なら図形どうしで）
  - 等間隔：D 横、E 縦（3 つ以上は図形どうし、2 つならスライドの端に合わせる）
  - 大きさ：W 幅、H 高さ、S 両方（最初に選んだ図形に合わせる）
  - X：2 つの図形の位置の入れ替え（それぞれの中心を入れ替える）
  - 貼り付け：I 画像として
  - 入れなかったもの：Alt のキー列や標準のショートカットで足りる、最前面・最背面、テキストだけ貼り付け、グループ化（Ctrl+G / Ctrl+Shift+G）、書式のコピー・貼り付け（Ctrl+Shift+C / V）、選択ウィンドウ（Alt+F10）。最初は入れていたが、重複なので外した。
  - 様子見：整列（L R T B C M）と等間隔（D E）は、Alt → H → G → A のキー列でも呼べる。今は 2 打鍵で済み、「スライドに合わせる／図形どうし」を自動で切り替える利点があるので残す。Alt のキー列で試して不便がなければ外す。
- 確かめたこと：PowerPoint（Office 16）を COM で動かし、整列・等間隔・大きさ・入れ替えが期待どおり動くことと、図形を選んでいないときや数が足りないときに知らせることを確認した。キー操作（クイックメニューからの呼び出し）と画像として貼り付けは、実機で未確認。
- 今後：足りない機能は要望を聞いて足す。候補は `ideas.md` の「アプリ専用のもの」。

### 6. Shift 長押しモード（試作ができた：Space+F → Caps、`Lib/shift_hold.ahk`）
- 目的：Shift を押しながら打つと左手のホームポジションが崩れるのを、Shift を押し続けなくて済むようにして解く。
- 旧版（大文字入力モード、`Lib/archive/upper_mode.ahk`）が使いにくかった点：変換 + g などの BS がモード中に効かない。数字・記号が Shift 付きにならない。原因は、キーを横取りして英字だけ Shift 付きで送り直していたこと。
- 作り（案 A）：入ると `{LShift down}` で Shift を押したままにする。キーを横取りしないので、英字は大文字、数字・記号は Shift 側（Shift + 1 の「!」）になり、変換 + g の BS や Space + j などのレイヤーもそのまま使える。
- 終了：Esc / Caps / Space+Caps。**Enter（Enter キー、Space + g / h）で確定したとき**（Shift なしの Enter を送ってからモードを抜ける）。キー操作がない状態が 2 分続いたとき。Shift キーを物理的に押して離したとき。スクリプトの終了・再読み込み（Shift を必ず離す）。同じ Space+F → Caps をもう一度でも終了。
- 表示：画面左下に「Shift 長押しモード」のツールチップを出し続ける。
- 確かめたこと（別のプロセスから送ったキーで）
  - Shift を押したままにすると、`ab12` が `AB!"` になる。
  - 組み合わせのホットキー（変換 + g のような形）は発動し、BS が効く。Shift は外れない。
  - 「*」なしの単独キーのホットキーは、Shift を押したままの間は発動しない（Insert の再読み込みなど）。終了用のホットキーには「*」を付けて、モード中だけ有効にした。
  - 終了の各方法で Shift が離れること、外から Shift が離されたときに自動で終了すること、時間切れ、トグルでの終了。
- 実機で未確認：Space+F → Caps の呼び出しと、Caps・Space+Caps での終了。日本語 IME をオンにしたときの動き（大文字・記号は IME の未確定文字になる）。
- 仕様上の注意
  - 矢印キーは Shift 付きになり、範囲選択になる（Space + j / k / l / ; の移動も同じ）。マウスのクリックも Shift 付きになる。
  - ただし IME の F8・F9（変換 + b / n）は、モードは続けたまま、Shift を一時的に離して送る（`ShiftHold_SendPlain`）。Shift 付きだと半角・全角の変換が効かないため。Enter（Enter キー、Space + g / h）は、Shift なしで送ってからモードを抜ける（`ShiftHold_Enter`）。確認済み（モード中に通常の送り方だと `Shift+F8` / `Shift+Enter` になり、これらの関数だと `F8` / `Enter` になる）。ほかの割り当てを同じ扱いにしたいときは、同じ関数に替える。
  - モード中は、Shift 付きにしたくない操作のために、いったん終了する。
  - Space + A（左手で文字・記号）はモード中も使える。入力待ちの間だけ Shift を離し（`ShiftHold_Pause`）、打ったキーを Shift なしの文字で表から引いてから、Shift を戻して送る（`ShiftHold_Resume`）ので、送る文字にモードが反映される（例：Q → `P`、4 → `'`）。Shift を離さないと、数字や記号のキーが `!` などになって表に当たらない。Shift 側に文字がないもの（JIS で Shift + 0 など）は何も出ない。確認済み（別のプロセスから、Shift を押したままにして送った）。
  - 案 B（次の 1 文字だけ）、案 C（Shift 付きの記号を左手のキーに置く）、案 D（親指キーで Shift）は、案 A が使いにくいときの代わり。`ideas.md` に残す。

### 8. カーソル移動モード（実装済み：カタカナひらがな、`Lib/mouse_grid.ahk`）
- 目的：赤ポチでは大まかな移動が弱く、マウスへ持ち替えるとホームポジションが崩れる。キーで場所を指して近づき、仕上げは赤ポチに任せる。案の比較は `ideas.md` の「カーソル移動モード」。
- 作り（案 A）：キーボードの配置（`q`〜`p` / `a`〜`;` / `z`〜`/` の 10 × 3。数字列はホームポジションから遠いので使わない）を領域の地図にする。打ったキーの位置のマスの中央へカーソルが飛び、続けて打つとそのマスの中を 10 × 3 に分けて飛ぶ。既定は 1 階層（1 打鍵で終了、1 階層でも事足りそうなため）。`MOUSEGRID_MAX_DEPTH` を 2 にすると、2 打鍵目でそのマスの中を 10 × 3 に分けて飛び、そこで自動終了する（戻せるように機能は残してある）。最初の領域はカーソルのあるモニター全体。
  - 表示：領域の枠と区切り線（細い 1 px、薄い赤）、各マスの中央にキーの文字（黄）。クリックを通す透明ウィンドウを、見せる部分だけ `SetWindowRgn` で切り抜く。マスが小さくなると、先に区切り線、次にラベルを消す。案内は、カーソルのあるモニターの左下のツールチップ。
  - キー：BackSpace で 1 段戻る（`MOUSEGRID_MAX_DEPTH` が 2 以上のとき、やり直す）。Space+A → キーで、左手だけで右手側のマスを指す（Q → P、S → L など。Space+A の表を読む。backlog #9 と同じ仕組み）。Tab で領域を替える（各モニター → アクティブウィンドウ。飛んだ位置は領域の中央）。半角/全角で開始位置へ戻って終わる。Esc / Caps / カタカナひらがなでその場で終わる。操作がないまま 10 秒で終わる。
  - 赤ポチ・マウスとの連携：カーソルが最後に飛んだ位置から 3 px 以上ずれる、または物理の左・右・中ボタンが押されると、モードを自動で終える（`MOUSEGRID_AUTO_END`、`MOUSEGRID_MANUAL_PX`）。クリックのキーは置いていない。
  - 起動：`keymap/leader_keys.ahk` の `sc070:: MouseGrid_Start()`。割り当てなしだった `Leader_Kana()`（入力待ち）と、キー割り当て一覧の「かな →」の層は外した（一覧のレイヤーは 6 つ）。
- 確かめたこと（別のプロセスから送ったキーで、1920 × 1080 のモニター）
  - `q` で (96, 180)、続けて `5` は数字列なので使わず `t` で (86, 60)（領域 192 × 360 → 19 × 120）。
  - Tab で次のモニターの中央へ領域が移る。半角/全角で開始位置へ戻って終わる。Esc でその場で終わる。
  - Space+A → `s`（`l` のマス）で (1632, 540)、Space+A のあと BackSpace で開始位置へ戻る、表にないキー（`x`）は無視、Space+A → `q`（`p` のマス）で (1824, 180)。
  - カーソルを 10 px ずらすと、モードが自動で終わる（試験中に手元のマウスが動いて、意図せず終わることもあった）。
  - 画面を撮って、枠・区切り線・ラベルが領域に合わせて出ることを確認した。ツールチップも出る。
- 実機で未確認：カタカナひらがなキーでの起動と、赤ポチ側の物理ボタンでの終了（別のプロセスの入力は物理入力にならないので、ボタンの判定は確かめていない）。使い始めには、Insert でスクリプトを再読み込みする。
- 今後：使ってみて、2 段目以降の分け方、赤ポチでの自動終了が邪魔でないかを見直す。近くの部品への吸着（案 D）は、必要になったら足す。

### 9. Vimium C 風ヒントの左手入力（実装済み：`Lib/vimium_c_hints.ahk`、`Lib/key_wait.ahk`）
- 背景：右手でマウスを持ち、左手だけでラベルを打つ使い方の方が、ダブルクリックやカーソル移動のみの使い方より多い。ラベルの文字（`asdfjklghqweruiop`）には右手側のキーが多く、左手だけでは打ちにくい。
- 作り：ヒントの表示中に Space+A を押すと、次のキー 1 つを、Space+A の表（`leader_keys.ahk` の `Leader_SpaceA`）で右手側の文字に直してラベルの入力にする（Q → P、S → L、D → K、F → J、G → H など）。表は `IH_SpaceAChar()` が読むので、二重に書かない。
- あわせて、変換+g や Space+s のような「別のキーを送る割り当て」も、BackSpace や Tab として効く（`IH_LayerSc()`。`principles.md` の「モードの中でのキーの扱い」）。
- 戻せるように：親指キーでクリックの種類を切り替える旧動作（Space：ダブルクリック、変換：右クリック、無変換：カーソル移動のみ）は残してある。`VIMIUMC_THUMB_CLICK` を `true` にすると戻る（既定は `false`）。旧動作のときは、親指キーに意味があるので、Space+A の左手入力と変換+g などの BackSpace は使えない。
- 確かめたこと（別のプロセスから送ったキーで、ボタン 20 個の試験用ウィンドウ）
  - Space+A → `s` でラベル `l` が選ばれ、そのボタンがクリックされる。
  - ラベルの 1 文字目を打ったあと、Space+s と変換+g のどちらでも 1 文字戻る。
  - `VIMIUMC_THUMB_CLICK` を `true` にすると、Space を押したあとのラベルでダブルクリックになる。
- 実機で未確認：実際の Space+A の押し方（Space を押しながら A）での使い心地。

### 10. InputHook モードの共通の骨組み（実装済み：`Lib/key_mode.ahk`）
- できたこと：`IHM_Run(st, opts)` / `IHM_Finish(st, result)`。モードは状態オブジェクト `st` と、キーが来たとき・始めるとき・終わるとき・終わったときの表示の関数を渡すだけ。押しっぱなしの無視、押しているキーの記録、親指キーの読み替え（`IH_LayerSc`）、Space+A の左手入力（`IH_SpaceAChar`）、時間切れ、後始末は骨組みがやる。項目は `Lib/key_mode.ahk` の冒頭のコメント。
  - カーソル移動モード（`mouse_grid.ahk`）と Vimium C 風ヒント（`vimium_c_hints.ahk`）を移した。どちらも、キーの処理は「整えたキー（`{sc, name, left}`）を受けて、モード固有の処理をする」だけになった（`mouse_grid.ahk` は 303 → 259 行、`vimium_c_hints.ahk` は 472 → 409 行。骨組みは 131 行）。
  - Vimium C 風ヒントの旧の動作（`VIMIUMC_THUMB_CLICK` が true）は `layers: false` で読み替えを切り、キーをそのまま受け取る。
  - カーソル移動モードの赤ポチ検知のタイマーと `Critical`（`critical: true`）はモード側に残した。
- 確かめたこと（変更前の複製と、キーを送って同じ結果を比べた）
  - カーソル移動モード（17 の場面：選んで終わる、Space+A、表にないキー、深さ 2 での BackSpace・Space+s・変換+g、半角/全角、Tab、Caps、かな、無変換+a の無視、赤ポチの操作での終了、時間切れ）：同じ（終わるまでの時間を 0.5 秒単位に丸めた記録で、1 場面だけ境目で 0.5 秒ずれた。動きは同じ）。
  - Vimium C 風ヒント（18 の場面：ラベル、Space+A、Space+s / 変換+g で 1 文字戻す、Esc / Caps、表にないキー、無変換+a の無視、ラベルなし、Tab、時間切れ、旧の動作の Space（ダブルクリック）・同じキーをもう一度で戻す・変換）：同じ。
- 動きが変わったところ（カーソル移動モード）：Space+A の待ちの間に親指キー（Space・変換・無変換）を押しても、待ちをやめない。以前はやめていた（Vimium C 風ヒントとそろえた）。試験にはこの操作はなかった。
- 対象外にしたもの（下のぶつかりの調査のとおり）：`window_switch.ahk` の各モード、日付入力、`Leader_Run`、ワンショット修飾キー。キーの受け方の模型が違うため。
- 実機で確かめること：Insert で再読み込みして、カタカナひらがなでカーソル移動モード（Space+A、変換+g、Esc / Caps、赤ポチで自動終了）、Caps → s で Vimium C 風ヒント（Space+A、Space+s）。

#### 調査メモ（着手前）
- 背景：キーで分岐する仕組みは「メニュー（Gui）」と「InputHook（フォーカスを移さない）」に大別される。使い分けは、いまのアプリの状態へ直接作用する・頻度が高い・連続するなら InputHook、項目が多くて見て選ぶ・頻度が低いならメニュー。メニューにはまとめない。
- やること：カーソル移動モードと Vimium C 風ヒントが、次を別々に書いている。これを 1 つの部品にする。
  - 押しっぱなし（キーリピート）の無視と、押しているキーの記録（`held` / `keys`）
  - 親指キーの読み替え（`IH_LayerSc`）と、Space+A の左手入力（`leftHand`、`IH_SpaceAChar`）
  - Esc / Caps で取り消し、一定時間操作がないと終了（押すたびに数え直す）
  - 開始時にすでに押しているキーの無視、`IH_ModeBegin` / `IH_ModeEnd`、終了の後始末（タイマー・InputHook の停止）
- この部品の対象は、イベントでキーを受ける型（`KeyOpt("{All}", "NS")` + `OnKeyDown`）だけ。カーソル移動モード、Vimium C 風ヒント、これから作るモード。
- 候補の設計：`Lib/key_wait.ahk` が大きくなるので、新しい部品（例：`Lib/key_mode.ahk`、関数は `IHM_` で始める（`KM_` は割り当て一覧が使っている））に置く。モードは「名前、時間切れの秒数、キーが来たときの関数、終わったときの関数、オプション（左手入力、読み替え、開始時に押しているキー、Critical）」を渡して起動する。キーが来たときの関数には、整えた「扱うスキャンコードと文字」だけを渡す。
- 現状の機能とのぶつかり（調べた結果）
  - 対象外にするもの：アプリ切り替え・タブ切り替え・ウィンドウの大きさ・モニター移動（`window_switch.ahk`）、日付入力、入力待ち（`Leader_Run`）、ワンショット修飾キーは、「1 キーごとに InputHook を張り直して Wait。押したキーで終わり、ループで繰り返す」型。キーの受け方の模型が違う。一つに寄せると、キー間の取りこぼしや Alt を押したままにするタイミングが変わる恐れがある。今回は寄せない。これらのモードでは「ほかのキー：決定」なので、親指キーの読み替えも足さない。
  - カーソル移動モードの赤ポチ検知のタイマー（`st.poll`）と `Critical()`：モード固有。骨組みには入れず、「キーの処理を Critical にする」オプションだけ用意する。
  - Vimium C 風ヒントの旧の動作（`VIMIUMC_THUMB_CLICK` が true）：親指キー自体に意味があるので、読み替えを切るオプションが要る。無変換を受ける `#HotIf IsObject(VimiumC_session)` のホットキーも残す。
  - モードの状態を入れる変数（`MouseGrid_session`、`VimiumC_session`）：`#HotIf IsObject(...)` や試験の確認で使っているので、モードごとに残す（骨組みは状態オブジェクトを返すだけ）。
  - `IH_waiting` と共有の `IH_hook`：`#HotIf !IH_waiting`（レイヤー、Insert、ドラッグの取り消し）と、`#HotIf IH_waiting && IH_hook.InProgress`（入力待ちで無変換を渡す）はそのまま使える。骨組みは独自の InputHook を持ち、共有の `IH_hook` は使わないので、競合しない（現状のこの 2 モードと同じ）。
  - Shift 長押しモード（`ShiftHold_IsOn()`）中にこのモードを開くと、Caps は `*sc03A:: ShiftHold_Stop()` が先に働き、モードの取り消しにならない可能性がある。今のモードでも同じで、骨組みで悪化しないが、実機で確かめておく。
  - `keymap_view`（割り当て一覧）とキー割り当ての編集：骨組みはキー割り当てのファイルに手を入れないので影響なし。
- 進め方：これまでの試験の考え方（変更前の複製と、キーを送って同じ結果を比べる）で、カーソル移動モードと Vimium C 風ヒントを 1 つずつ移す。カーソル移動モードを先に移し、テストを流したあと Vimium C 風ヒントを移す。実機での確認項目：Space+A、変換+g、Esc / Caps、時間切れ、赤ポチの操作での自動終了。
