# 方針

PC 作業全般を高速化するための、アプリに依存しない汎用的な機能を作るときの基準。
機能を足す・キーを割り当てるときは、まずここを見る。

作成日：2026-10-08

## 基本方針
- 特定のアプリに依存せず、どのアプリでも使えること。ただし、下の「アプリ専用の機能を入れる条件」を満たすものは例外として入れてよい。
  - アプリごとの個別対応（特定アプリ向けの分岐やチューニング）は作り込まない。OS の標準の仕組み（UI Automation など）で足りない箇所は、操作で補う（例：親をたどるキー）。
    - ここでいう個別対応は、汎用の機能の中にアプリ名での分岐やアプリごとの癖への調整を混ぜること。アプリ専用の機能は、汎用の機能とは別の部品として置く。
- ホームポジションを崩さないこと。Shift / Ctrl / Alt の同時押しや、手を大きく動かす操作は避け、ホームポジションのキーと親指キー（Space・変換・無変換）で完結させる。
- 今足りない 3 つの領域を埋める。
  - 画面の中の対象を、キーボードだけで操作する
  - 画面や選択の中身を取り出して加工する
  - 作業の文脈（ウィンドウの配置、何をしていたか）を覚えておく

## キー割り当ての考え方（地価）
- キーの「地価」は、ホームポジションからの近さで決める。指を動かさずに押せるほど高い。
  - 最高：親指キー（Space・変換・無変換）、ホーム段（`a s d f` / `j k l ;`）。
  - 高い：最高のキーから指を少し伸ばせば届くキー。
    - ホーム段の端・隣：`CapsLock`、`g` `h`、`:`
    - 上段で人差し指・中指・薬指が届くもの：`w e r` / `u i o` など
  - 低い：数字列、下段（`z x c v b n m , . /`）、端のキー（`\` `^` `]` など）、手を大きく動かすキー。
- 数字キーの行は、ホームポジションから遠いので、新しく作る機能の候補に入れない。
  - 1 つのキーに機能を割り当てるときだけでなく、キーボードの配置を画面や選択肢の地図にして、多くのキーをまとめて使う機能でも同じ。使うのは文字キーの 3 段（上段・中段・下段）まで。
  - 例外は、数字そのものを入力するなど、キー自体に意味があるとき。
- 空いている高地価のキーは数が少ない。使う頻度が高く効果が大きい機能から順に、地価の高い空きへ置く。
- 頻度の低い機能は、低地価のキーかクイックメニューに回す。高地価の空きを使わない。
- 同じ地価なら、押す回数が少ない割り当ての方が高い（同時押し・単打 ＞ 入力待ちの 2 打鍵目）。
- 対になる動作（左 / 右、大 / 小、戻す / やり直す など）は、同じ手の「小指と人差し指」「薬指と中指」のペアに置く（例：`q` / `r` で左回転 / 右回転、`a` / `f` で前 / 次、`w` / `e`、`s` / `d`）。同じ段で、外側の指を逆向き・前者、内側の指を順向き・後者にそろえると覚えやすい。
- 押した状態が保持されるキー（CapsLock、カタカナひらがなキー。半角/全角も同じ性質）は、押している間だけ組み合わせる「親キー」（`keymap\hold_keys.ahk` の `起点 & キー` の起点）には使えない。入力の状態が保持され続けるため。使えるのは次の場合（初期に確認済み）。
  - 押したあとに離して、次のキーを待つ「入力待ちの起点」（`keymap\leader_keys.ahk`）。CapsLock はこれに使っている。カタカナひらがなキーも起点に使える（いまは割り当てていない）。
  - 設定の「子」（`無変換 & かな` のような、親キーを押したまま打つキー）。
  - モードの中では、Caps と半角/全角は、離しても押したままと返ることがあるので、開始時に押しているキーを調べるときは除く（`Lib\key_mode.ahk` の `_IHM_MarkHeld`）。

## 外部ツールから呼ぶキー（「特殊」）
Logi Options+ など、マウスやデバイスの設定ツールのボタンにキーの組み合わせを割り付け、そちらから呼ぶためのキー（`keymap\leader_keys.ahk` の起点キーの欄。キー割り当ての画面の「特殊」層）。例：`Ctrl+Shift+Alt+F12`。
- 基本のキーボード入力では使わない。手で押すことを想定しないので、上の「地価」の考え方（押しやすさ）は当てはめない。
- 押しにくく、既存のホットキーやアプリのショートカットと重なることがほとんどありえない組み合わせを選ぶ（修飾キーを 3 つ以上重ねる、F12 や F13 以降のファンクションキーと組み合わせるなど）。手で押しにくいほど、誤って押したり、ほかと競合したりしない。
- 使う前に、このリポジトリ内（`keymap\`、`Lib\`）ですでに使われていないことを探す。
- Alt を含む組み合わせは、アプリによって押して離すとメニューが反応することがある。実機で気になるときは、Alt を含めない組み合わせに変える。

## モードの中でのキーの扱い
独自の InputHook でキーを受けるモード（カーソル移動モード、Vimium C 風ヒントなど）を作るときの決まり。
- モードの操作キー（BackSpace、Tab、Enter、Esc、矢印、Delete など）は、そのキーを直接押したときだけでなく、キー割り当てが「そのキーを送る」形で呼んだとき（変換 + g、Space + s など）も、同じ操作として扱う。BackSpace に限らない。
  - 理由：モードの間は、押しながら使うレイヤーのホットキーが止まる（`#HotIf !IH_waiting`）。しかも自分の `SendInput` は自分の InputHook に届かない。何もしないと、変換 + g は `g` だけが届いて、モードの文字キーとして働いてしまう（例：グリッドのマスを選んでしまう）。
  - 作り方：`Lib\key_mode.ahk` の `IHM_Run()` でモードを動かす。リピートの無視、親指キーの読み替え（`IH_LayerSc()`）、Space+A、時間切れ、後始末は骨組みがやるので、モードは「整えたキーを受けて、モード固有の処理をする」だけを書く。無いとき（キーを 1 つずつ待つ型のモードなど）は、分岐の前に `IH_LayerSc()` を自分で通す。
  - 対応は `keymap\hold_keys.ahk` から自動で読む（`起点 & キー::  SendInput("{キー}")` と、Enter を送る `ShiftHold_Enter()`）。モード側に同じ対応を書かない。割り当てを変えれば、モードもそれに従う。
- 親指キーを押したまま打ったキーのうち、送るキーのない割り当て（関数を呼ぶもの、`^{Tab}` のような修飾付きのもの）は、モードの文字キーとして扱わず無視する（`ignoreOthers`）。モード中に誤って選ぶのを防ぐため。Esc と Caps は取り消しなので、親指キーを押していても常に効かせる。
- 親指キーそのものに意味を持たせたいときは、短押しだけ受ける（`onThumbTap`。Vimium C 風ヒントのクリックの種類の切り替え）。長押しや他のキーとの組み合わせは、上の読み替えのままにする。
- 左手だけで右手側の文字を入力する Space+A は、文字を打つモードでも引ける（`IH_SpaceAChar()`。`leader_keys.ahk` の表を読むので、表を二重に書かない）。右手でマウスを持っていても、左手だけで操作できるようにするため。
- 試験では、別のプロセスから送るキーの `SendLevel` を既定の 0 のままにする。実行中の `main.ahk` のホットキーが反応して、操作中のウィンドウへキーが届くのを避けるため。0 でもモード側の InputHook は受け取る。

## アプリ専用の機能を入れる条件
汎用であることが望ましいが、次の 2 つを両方満たすなら、アプリ専用の機能も実装の候補に入れる（例：クイックメニューの「VS Code」、検討中の PowerPoint の詰め合わせ）。
- 使う頻度が明確に高い。
  - そのアプリで毎日のように行う作業で、操作の手数が多い、または何度も繰り返すもの。たまにしか使わないものは入れない。
- 覚えておく負担が小さい。
  - 呼び出すキーを覚えなくても、画面に小さなメニューやポップアップが出て、それを見ながら次のキーを打てば実行できる（クイックメニューのような 2 打鍵の形）。
  - 専用のキーを、地価の高い空きに置かない。呼び出しは 1 か所（クイックメニューのカテゴリ、または 1 つの入口のキー）にまとめる。

入れるときの決まり：
- 実現の手段は、軽い順に選ぶ。上で足りるなら、下へ進まない。
  1. そのアプリの標準のショートカットキーを送る。
  2. Alt で呼び出せるリボン・ツールバーの機能を、キーの並び（Alt → H → … など）で送る。
  3. 1・2 では手数や待ち時間がかかりすぎる、または 1 打鍵で目的が果たせないときだけ、アプリの内部の仕組み（COM、公式のコマンド）で機能を作る。
  - 3 に進む目安は、標準の操作では明確に時間がかかること（手数が多い、画面の切り替えを待つ、複数の対象に繰り返す、状態によって手順が変わるなど）。時間がかからないものは、1・2 の呼び出しだけをメニューに並べる。
  - 1・2 は、アプリのバージョンや設定で変わりやすい。変わって動かなくなったときは、直すか外す。
- 汎用の機能とは別の部品にまとめ、まとめて外せるようにする（機能の本体は `Lib\`、呼び出しだけを `keymap\` かクイックメニューに置く）。
- そのアプリが前面にあるときだけ有効にする（`#HotIf WinActive("ahk_exe …")`）。ほかのアプリでの操作には影響させない。クイックメニューのように、呼ばれたときだけ動くものは、ほかのアプリで選ばれても壊れないことを確かめる。
- 画面の見た目や位置に頼る操作（座標のクリックなど）は避ける。
- 頻度が下がった、またはアプリを使わなくなったときは、`Lib\archive\` へ移す。

判断に迷うときは、「そのアプリを使う人が、メニューを見ながら選ぶだけで使えるか」と「汎用の機能で代わりにならないか」を先に確かめる。
